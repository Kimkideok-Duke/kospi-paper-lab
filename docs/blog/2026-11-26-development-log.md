# 5초 감시에서 매매 복기 차트까지: 관측·판단·표시를 분리한 하루

2026-11-26 개발 기록 · 2026-11-27 작성 · Node.js · SQLite · 모의투자 · TradingView Lightweight Charts

11월 26일에는 모의투자의 운영 경계와 결과를 설명하는 화면을 함께 바꿨다. 개인별 원장을 분리하고 뉴스·공시 반응과 일별 복기를 추가한 뒤, 보유 감시를 5초로 줄이고 종가를 별도로 검증했다. 마지막에는 직접 그리던 거래 차트를 기성 차트 엔진으로 교체했다.

변경을 관통하는 문제는 하나였다. 관측한 가격, 당시 매매 판단, 나중에 읽는 설명을 같은 것으로 취급하면 잘못된 결론을 만들기 쉽다. 더 자주 조회했다고 모든 체결을 안 것은 아니며, 더 보기 좋은 차트가 당시의 체결 가능성을 증명하지도 않는다. 각 자료의 출처와 적용 범위를 나누는 데 초점을 맞췄다.

이 글은 한국시간 **2026-11-26 00:00 이상, 2026-11-27 00:00 미만**의 커밋을 대상으로 한다. 그중 실제 소스 변경 커밋은 10개다. 문서만 게시한 `8fe5f19`는 소스 변경 집계에서 제외했다. 설명의 최종 기준은 [bfd7a39](https://github.com/Kimkideok-Duke/kospi-paper-lab/commit/bfd7a3991fb3002119b3cd1a4738b4851f14d275)다. 같은 날 앞서 작성한 [구조 중심 개발기](2026-11-26-marketlab-engineering.md) 이후 바뀐 5초 감시와 차트 표시까지 포함해 하루의 최종 동작을 정리한다.

## 1. 로그인 화면보다 중요한 것은 원장 선택의 경계였다

이전의 공통 로그인 구조에서는 로그인 이후 모든 요청을 같은 소유자로 처리하는 방식이 문제가 될 수 있었다. 개인 계정을 추가하면서 사용자 ID를 요청 헤더나 쿼리에서 받아 원장을 고르지 않도록 했다. 서버 세션이 사용자를 결정하고, 사용자별 DB와 암호화 키를 선택한다. 국내·미국장 원장은 분리하되 같은 사용자의 API 연결과 토큰은 공유한다.

[local-host.mjs](../../server/local-host.mjs), [local-accounts.mjs](../../server/local-accounts.mjs), [local-tenants.mjs](../../server/local-tenants.mjs)가 이 경계를 맡는다. 기존 소유자 원장을 초기화하지 않고 새 사용자를 별도 저장소로 분리했다. 외부 접속 게이트웨이도 호출자가 보낸 소유자 인증 헤더를 신뢰하지 않는 방식으로 맞췄다.

이 분리는 웹 사용자가 다른 사용자의 원장을 읽지 못하게 하는 설계다. 서버 PC 운영자로부터 저장 파일을 숨기는 별도의 암호학적 격리라고 소개하지 않는다. 운영·이전 범위는 [계정 문서](../accounts.md)에 기록했다. 실거래 준비 모듈은 운영·빌드 경로에 연결하지 않았다.

## 2. 뉴스 반응과 지정가 주문은 정기 분석을 보완한다

10분마다 신규 후보를 분석하는 구조만으로는 그 사이에 들어온 중요 정보를 다루기 어렵다. [market-events.mjs](../../server/market-events.mjs)는 공개 피드를 공통으로 수집하고, 사용자별로 처리한 정보와 추가 분석 대기 상태를 보존한다. 처음 정상 수집한 피드는 기준 목록으로 삼아 과거 기사로 새 반응을 만들지 않는다. 중복 정보와 오래된 정보도 반복 매매의 계기로 사용하지 않는다.

뉴스·공시 수집과 매매 실행은 다른 단계다. 중요 제목을 발견해도 최신 정규장 시세·환율·호가 등 기존 조건을 통과해야 모의 주문을 검토한다. 차단되거나 실패한 정보원은 장애로 표시하고 공시가 없다고 단정하지 않는다. 당시 [운영 문서](../market-events.md)에는 일부 해외 정보원의 접근 차단도 기록되어 있다. 이 글을 작성하면서 외부 피드의 현재 접속 상태를 다시 확인하지는 않았다.

주문 방식도 가격 도달 후 반응하는 방식에 사전 지정가 대기를 더했다. 일반 매수 후보는 기준가보다 낮은 지정가로 기다리고, 강한 상승세나 장중 이벤트는 즉시 체결 우선 방식을 사용한다. 보유분에는 목표가 주문을 유지하되 손절·악재·추세 약화에 따른 보호 매도가 우선한다. [paper-model.mjs](../../server/paper-model.mjs)는 주문과 부분 체결, 만료, 취소를 별도 상태로 관리한다.

감시하지 못한 사이에 목표가를 통과했을 것이라는 추측으로 체결을 생성하지 않는다. 주문을 미리 두는 모형도 실제 거래소의 대기 순번과 모든 유동성을 재현하지는 못한다.

## 3. 5초 감시는 타이머 숫자만 줄이는 변경이 아니었다

보유 종목과 기존 미체결 주문의 감시를 1분에서 5초로 바꿨다. 신규 종목 분석은 10분을 유지한다. 뉴스·공시 수집 주기를 모두 5초로 바꾸거나 전체 종목 목록을 계속 다시 읽는 방식으로 확대하지 않았다.

[monitor-batch.mjs](../../server/monitor-batch.mjs)는 직전 실행이 끝난 뒤 다음 실행을 예약한다. 늦어진 회차를 한꺼번에 따라잡지 않고 실행이 겹치지 않도록 한다. 오류가 이어지면 10·20·40·60초로 감속한다. 장외 유지관리와 보조 시세 조회는 1분 간격을 유지한다. 모든 증권 API 호출은 기존 공통 그룹별 대기열을 이용한다.

자주 관측하면 저장 비용도 늘어난다. 자산 표시용 이력은 같은 분의 마지막 관측으로 정리하면서, [paper-analytics.mjs](../../server/paper-analytics.mjs)에 관측된 자산 고점과 최대 낙폭을 별도로 보존했다. 표시용 이력을 줄였다는 이유로 분 안에서 관측한 위험까지 지워지지 않도록 한 것이다.

화면의 보유 시세 조회는 저장된 서버 관측을 읽는다. 반면 뒤에서 설명할 차트 팝업의 과거 분봉 조회는 필요한 경우 외부 API를 사용한다. 두 요청 경로를 구분해야 화면 갱신과 외부 호출량을 정확히 설명할 수 있다.

## 4. 종가를 확인했다는 표시에는 완료 조건이 필요했다

복기에 마지막 저장 평가금액이 포함된다는 한계가 있었다. 이를 보완하면서 현재가를 한 번 더 읽는 대신, 해당 거래일의 일봉 종가를 별도로 확인하는 절차를 추가했다.

[closing-audit.mjs](../../server/closing-audit.mjs)는 당일 거래한 종목과 마감 시점 보유 종목 전체를 대상으로 한다. 여기서 전체는 거래소의 모든 상장 종목이 아니라 해당 모의 원장의 평가 대상 전체다. 기존 복기 관측의 30종목 제한은 종가 확인에 적용하지 않는다.

국내 기준은 선택된 토스 KRX·NXT 통합 일봉 종가이며 시간외장 종료 후 확인한다. 미국은 정규장 공식 일봉 종가를 사용한다. 거래일별 장 일정을 확인하고 해당 종료 시각 1분 후부터 조회한다. 요청한 날짜·통화·유효한 가격이 맞는지 검사하고, 실패한 종목만 다시 확인한다. 회당 요청 예산을 두어 한 번에 모두 처리하지 못하면 다음 실행에서 이어 간다.

전 종목의 가격을 확인한 것과 원화 평가를 완성한 것도 구분했다. 미국장의 마감 이전 저장 환율이나 과거 원장 근거가 부족하면 가격 확인은 완료해도 평가 완료로 표시하지 않는다. 직전 거래일의 확인 평가가 없으면 당일 평가손익을 임의로 계산하지 않는다. 기존 보고서는 보존하고 조회 시 별도 확인 결과를 덧붙인다.

당일 [변경 기록](../changes/2026-11-26.md)에는 실제 화면의 완료·대기 상태 확인이 남아 있다. 이 글에서는 개인 원장을 조회하거나 모든 날짜의 종가 확인이 현재 완료됐다고 주장하지 않는다.

## 5. 복기는 종목 단위로 읽고 개별 판단은 차트에서 찾는다

부분 체결이 많은 종목을 체결별로 나열하면 같은 판단이 반복되어 하루의 결과를 읽기 어렵다. [stock-review.mjs](../../server/stock-review.mjs)는 같은 종목의 당일 체결을 묶어 매매 이유, 실현손익과 기록된 비용, 사후 비교 가능한 개선점을 정리한다. 이전 보유분만 매도한 날과 당일 새로 진입한 날을 구분한다.

개별 체결 판단을 없앤 것은 아니다. 차트 표식에 마우스를 올리면 당시 판단 이유를 확인하고 체결 목록에서 원래 시각·가격·수량을 선택한다. 복기에서는 같은 종목의 하루 전체 차트로 이동할 수 있다.

사후 대안은 저장된 5~7분 뒤 관측가가 있는 범위에서만 비교한다. 매수·매도 방향에 따른 가격상 유불리와 비교 누락 수를 보여주지만, 부분 체결별 가격차를 합산해 실행 가능한 대안 수익으로 소개하지 않는다. 거래 후 더 좋은 가격이 있었다는 사실과 당시 같은 수량으로 체결할 수 있었다는 주장은 다르다.

일별 전략 보완도 별도 경계를 유지한다. [daily-review.mjs](../../server/daily-review.mjs)와 [strategy-policy.mjs](../../server/strategy-policy.mjs)는 표본이 부족하면 기존 규칙을 유지하고, 조건이 충족될 때만 제한된 진입 기준 변경을 다음 유효 거래일에 적용한다. 차트패턴 비교는 [별도 분석 메뉴](../chart-patterns.md)로 두며 주문 조건에 연결하지 않았다.

## 6. 더 정확한 자료와 더 읽기 좋은 차트는 다른 문제였다

처음 거래 차트는 저장된 관측가로 그렸다. 그런데 보유 감시는 5초인데 차트는 분당 마지막 관측만 보존하고 있었다. 같은 5초 구간만 합치도록 보관 방식을 바꾸고, 과거 흐름은 토스 API 1분봉의 시가·고가·저가·종가·거래량으로 보완했다. 이전에 저장하지 않은 5초 경로를 소급 생성하지는 않는다.

[chart-candles.mjs](../../server/chart-candles.mjs)는 최대 200봉씩 제공된 `nextBefore`를 따라 조회한다. 페이지 경계의 중복을 제거하고 통화·OHLC 범위·거래량을 검증한다. 사용자별 메모리 캐시와 진행 중 요청 공유를 적용하며, 12페이지 상한이나 조회 실패는 전체 완료로 표시하지 않는다. 팝업은 기존 유효 토큰을 재사용하고, 팝업 때문에 별도 토큰을 발급하거나 매매 원장을 잠그지 않는다.

자료를 개선한 뒤에도 화면 문제가 남았다. 직접 그린 차트는 캔들이 촘촘하고 매매 화살표가 겹쳤다. 최종 변경에서는 수동 Canvas 렌더러를 제거하고 **TradingView Lightweight Charts 5.3.0**을 적용했다. 기성 엔진이 축·캔들·거래량·크로스헤어·확대·이동을 담당한다. 선택 매매 주변을 기본으로 보여주고 전체 기간과 1·5·15분봉을 선택할 수 있다.

완성된 외부 차트 위젯과 차트 엔진은 다르다. 위젯의 국내 종목 지원과 사용자 자료 입력 제한 때문에 팝업에는 토스 자료를 사용하는 엔진을 적용했고, 원본 사이트 차트를 여는 링크를 별도로 제공했다. 공식 배포 패키지의 무결성을 검사하고 [라이선스·NOTICE·출처](../../web/vendor/lightweight-charts/)를 포함했다. 런타임 외부 스크립트나 보안 헤더 완화는 추가하지 않았다.

표시용 시각도 정리했다. API 1분봉의 종료 시각을 봉 시작 시각으로 변환해 5·15분봉을 집계한다. 같은 봉·같은 방향의 부분 체결은 묶고 선택 체결은 중복 집계 없이 별도 강조한다. 표식의 가로 위치는 해당 봉에 맞추되, 개별 상세에는 실제 초 단위 시각과 체결가를 보존한다. 숨긴 관측 시리즈가 시간축을 과밀하게 만들지 않도록 표시하지 않는 자료는 시리즈에서 제외했다.

5초 감시는 모든 체결을 수신하는 스트림이 아니며, 네트워크와 호출 대기열 때문에 일정 간격을 보장하지 않는다. 1분봉으로 초 단위 전체 경로를 복원할 수도 없다. 종목별 복기와 패턴 비교는 저장된 표본에 한정되며 실행 가능한 대안 전략의 성과를 입증하지 않는다. 기성 차트 엔진은 가독성과 조작을 개선하지만 시세 원천과 모의 체결 모델의 한계를 없애지는 않는다.

공개 글에는 개인 거래·계좌·시세 기록과 인증 정보를 포함하지 않았다. 더 자세한 변경 근거는 [당일 변경 기록](../changes/2026-11-26.md), 현재 사용 방법은 [거래 차트 문서](../trade-chart.md)에서 확인할 수 있다.
