# 개인별 로그인과 모의계좌 (로컬 서버)

마켓랩 전용 개인 계정으로 로그인한다. 토스 앱 로그인 정보를 받는 소셜 로그인은 아니며 토스 비밀번호를 입력받거나 저장하지 않는다. 패스키는 아직 제공하지 않는다.

## 기존 소유자

- 기존 PC에서는 호스트 설정의 소유자 아이디와 비밀번호 해시를 최초 한 번 가져온다. 이전 외부 접속 아이디·비밀번호로 새 로그인 화면에서 로그인한다. 공통 브라우저 Basic 인증은 제거한다.
- 기존 `campaign.sqlite`와 `key`를 그대로 사용한다. 기존 국내·미국장 잔고, 보유 종목, 거래내역과 암호화 API 연결을 초기화하지 않는다.
- **내 계정**에서 비밀번호를 변경하거나 다른 사용자를 초대할 수 있다. 비밀번호를 바꾸면 다른 기기의 세션은 모두 해제된다.

## 새 사용자

- 소유자의 **내 계정 → 사용자 초대**에서 발급한 링크로 가입한다. 링크는 24시간 유효하며 한 번만 사용할 수 있다. 새 사용자는 12~128자 비밀번호를 직접 정한다.
- 각 사용자는 국내·미국장에 별도로 원금 1,000만 원인 모의계좌를 갖는다. 설정에서 **자신의 Client ID와 Client Secret**을 연결해야 자동 분석이 실행된다. 본 서버의 공인 IP를 본인 토스증권 API 허용 IP에 등록해야 한다.
- 계정이 달라도 서버 PC와 송신 IP는 같다. 국내·미국장 안에서는 그 사용자의 연결과 토큰을 공유한다. 동일 Client ID를 다른 마켓랩 사용자에게 중복 연결할 수 없다. 별도 PC나 외부 프로그램의 API 사용까지 차단하지는 못한다.
- 웹 화면에서 다른 사용자의 원장, API 키, 설정을 조회하거나 변경할 수 없다. 소유자에게도 다른 사용자의 거래내역을 열람하는 웹 기능은 제공하지 않는다. 서버 운영자는 PC의 저장 파일과 실행 환경을 통제하므로 웹 계정 분리는 운영자로부터의 암호학적 비공개를 뜻하지 않는다.

## 저장·인증 경계

- 계정과 세션: 데이터 디렉터리의 `accounts.sqlite`. 비밀번호는 사용자별 salt와 scrypt 해시만 저장하며 세션·초대 토큰도 해시로 저장한다.
- 개인 원장: `users/<서버가 생성한 사용자 ID>/campaign.sqlite`. 소유자 원장은 기존 루트에 남긴다. 새 사용자의 API 암호화 키는 마스터 키에서 사용자별로 파생하며 브라우저에 전송하지 않는다.
- 사용자 ID는 유효한 서버 세션에서만 결정한다. 요청 헤더나 쿼리의 사용자 ID로 원장을 선택하지 않는다. 모든 데이터 API와 대시보드는 로그인해야 접근할 수 있다.
- 세션은 7일 후 만료되며 HttpOnly·SameSite=Strict 쿠키를 사용한다. HTTPS 게이트웨이를 통과한 쿠키에는 Secure를 추가한다. 변경 요청은 동일 출처에서만 허용하고 반복 로그인 실패를 제한한다.
- 10분 분석·1분 감시는 등록된 사용자별 원장과 암호화 키로 실행한다. 토스 호출은 모든 사용자가 기존 공통 그룹별 제한 대기열을 이용한다.
- 새 PC에 호스트 설정도 계정 DB도 없으면 최초 실행 때 데이터 디렉터리에 `owner-login.txt`를 만들며 초기 소유자 자격정보는 해당 비공개 로컬 파일에서 확인한다. 기존 계정 DB가 있으면 다시 초기화하지 않는다.

## 운영과 공개 소스

`node scripts/local.mjs`가 계정·원장 격리를 적용한다. 외부 접속에는 `node scripts/gateway.mjs`를 로컬 8766 포트의 HTTPS 터널 뒤에서 실행한다. 이 게이트웨이는 개인 세션을 그대로 전달하고 호출자가 보낸 소유자 인증 헤더는 제거한다. 사이트 Worker 빌드는 이 로컬 계정 호스트와 다른 실행 경로이며 다중 사용자 서비스로 배포하면 안 된다.

이전에는 공통 로그인 뒤에서 모든 화면을 같은 소유자로 처리했다. 기존 게이트웨이 코드와 새 서버를 섞지 말고 두 프로세스를 함께 갱신한다. 외부 공개 시 API는 로그인 화면과 가입 처리 외에는 미인증 요청을 거부해야 한다.

백업·이전은 서버를 중지하고 `accounts.sqlite`(WAL 포함), 루트 원장과 `key`, `users/`를 한 세트로 보존한다. DB·키·계정 해시·세션·초대 링크·로그인 안내 파일을 GitHub에 올리지 않는다. 공개 저장소에는 소스와 가짜 자격정보를 쓰는 테스트만 포함한다.

## 실거래 제한

실제 주문 코드는 계속 비활성이고 로컬 호스트·빌드·배치에 연결하지 않는다. 이번 사용자 격리가 실거래 전환 승인을 의미하지 않는다. 향후 전환 시에는 로그인한 사용자와 토스 계좌 소유권의 대조, 주문별 권한 검증, 재인증, 사용자별 주문 원장·한도·감사 기록, 모의/실전 환경 분리 등을 별도로 구현하고 검증해야 한다. 현재 기능은 모의매매 전용이다.
