# 토스증권 호출 한도 관리

2026-11-25 한도 오류 원인: 미국 NASDAQ·NYSE·AMEX의 종목 목록을 클라이언트별 350ms 간격으로 조회했지만, 실제 `STOCK_ALL` 응답 헤더 한도는 초당 1회였다. 분석이 중단되어 일별 유니버스가 저장되지 않았고 다음 분석·수동 요청에서도 같은 조회를 반복했다.

현재 운영 경로의 모든 토스증권 REST 호출(토큰 발급, 국내·미국장 분석, 보유 감시)은 `server/market-transport.mjs`의 **프로세스 전체 공통 그룹별 대기열**을 사용한다. 인스턴스마다 제한을 따로 계산하지 않는다. 일반 앱의 HTTP 화면 요청은 토스 호출 대기열과 구분된다.

- 공식 그룹별 기본 한도에 안전 여유를 두고 호출 간격을 정한다. `STOCK_ALL`·`ACCOUNT`는 최소 1.1초 간격이다.
- 모든 응답의 `X-RateLimit-Limit`를 확인하고 실제 한도가 더 낮으면 즉시 간격을 늘린다. `Remaining=0`이면 `Reset`이 지날 때까지 그룹 전체가 기다린다.
- 429 응답은 `Retry-After`, `Reset`, 지수 백오프 중 가장 긴 시간에 여유·지터를 더해 기다린다. GET만 최대 3회 시도한다. 과도하게 긴 대기나 반복 실패는 분석을 안전하게 중단하고 다음 실행에서 확인한다. 토큰 발급 POST는 자동 재전송하지 않는다.
- 동일한 GET은 진행 중 요청을 공유한다. 종목 목록은 프로세스 메모리에 최대 6시간, 성공한 유니버스는 기존 계좌 상태에 거래일별로 보관한다. 짧은 시세 캐시는 250ms, 호가는 100ms이며 거래 시 신선도와 유효 환율을 별도로 검증한다.
- `/api/quotes`, `/api/us/quotes`는 **서버 1분 감시가 저장한 시세**를 반환한다. PC·휴대폰·브라우저 탭이 늘어도 화면 조회 때문에 토스 API를 추가 호출하지 않는다. 최근 체결가 시각은 그대로 표시한다.
- `/api/health`의 `api`에는 실제 전송 수, 캐시·요청 공유 수, 429 및 재시도 횟수, 그룹별 감속 상태를 표시한다. 토큰·키·계좌번호는 포함하지 않는다.
- 이 전송 모듈은 실제 주문·취소 경로를 차단한다. 기존 실거래 준비 소스는 계속 비활성이다.

다른 PC나 별도 프로그램이 같은 Client ID를 동시에 사용하면 이 프로세스의 대기열 밖에서도 한도를 소비할 수 있다. 그런 경우에도 받은 응답 헤더와 429 대기 지시를 따른다. 외부 프로그램의 요청량까지 이 서버가 제한할 수는 없다.

공식 기준: [토스증권 Open API 개요의 Rate Limits](https://openapi.tossinvest.com/openapi-docs/overview.md), 2026-11-25 확인. 당시 `STOCK_ALL` 초당 1회와 `Retry-After`/`X-RateLimit-*` 의미를 확인했고 실제 응답에서도 `Limit=1`, `Remaining=0`, `Reset=1`을 확인했다.

수정은 거래 내역·잔고를 초기화하지 않으며, 10분 신규 분석·1분 보유 감시 주기는 유지한다. 과거 실패 이력은 보관하고 다음 분석이 정상 완료되면 활성 오류 표시가 해제된다.
