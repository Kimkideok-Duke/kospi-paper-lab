# 토스증권 호출 한도 관리

2026-11-25 한도 오류 원인: 미국 NASDAQ·NYSE·AMEX의 종목 목록을 클라이언트별 350ms 간격으로 조회했지만, 실제 `STOCK_ALL` 응답 헤더 한도는 초당 1회였다. 분석이 중단되어 일별 유니버스가 저장되지 않았고 다음 분석·수동 요청에서도 같은 조회를 반복했다.

현재 운영 경로의 모든 토스증권 REST 호출(토큰 발급, 국내·미국장 분석, 보유 감시)은 `server/market-transport.mjs`의 **프로세스 전체 공통 그룹별 대기열**을 사용한다. 인스턴스마다 제한을 따로 계산하지 않는다. 일반 앱의 HTTP 화면 요청은 토스 호출 대기열과 구분된다.

- 공식 그룹별 기본 한도에 안전 여유를 두고 호출 간격을 정한다. `STOCK_ALL`·`ACCOUNT`는 최소 1.1초 간격이다.
- 모든 응답의 `X-RateLimit-Limit`를 확인하고 실제 한도가 더 낮으면 즉시 간격을 늘린다. `Remaining=0`이면 `Reset`이 지날 때까지 그룹 전체가 기다린다.
- 429 응답은 `Retry-After`, `Reset`, 지수 백오프 중 가장 긴 시간에 여유·지터를 더해 기다린다. GET만 최대 3회 시도한다. 과도하게 긴 대기나 반복 실패는 분석을 안전하게 중단하고 다음 실행에서 확인한다. 토큰 발급 POST는 자동 재전송하지 않는다.
- 동일한 GET은 진행 중 요청을 공유한다. 종목 목록은 프로세스 메모리에 최대 6시간, 성공한 유니버스는 기존 계좌 상태에 거래일별로 보관한다. 짧은 시세 캐시는 250ms, 호가는 100ms이며 거래 시 신선도와 유효 환율을 별도로 검증한다.
- `/api/quotes`, `/api/us/quotes`는 **서버 5초 감시가 저장한 시세**를 반환한다. PC·휴대폰·브라우저 탭이 늘어도 화면 조회 때문에 토스 API를 추가 호출하지 않는다. 최근 체결가 시각은 그대로 표시한다.
- `/api/health`의 `api`에는 실제 전송 수, 캐시·요청 공유 수, 429 및 재시도 횟수, 그룹별 감속 상태를 표시한다. 토큰·키·계좌번호는 포함하지 않는다.
- 이 전송 모듈은 실제 주문·취소 경로를 차단한다. 기존 실거래 준비 소스는 계속 비활성이다.

다른 PC나 별도 프로그램이 같은 Client ID를 동시에 사용하면 이 프로세스의 대기열 밖에서도 한도를 소비할 수 있다. 그런 경우에도 받은 응답 헤더와 429 대기 지시를 따른다. 외부 프로그램의 요청량까지 이 서버가 제한할 수는 없다.

공식 기준: [토스증권 Open API 개요의 Rate Limits](https://openapi.tossinvest.com/openapi-docs/overview.md), 2026-11-25 확인. 당시 `STOCK_ALL` 초당 1회와 `Retry-After`/`X-RateLimit-*` 의미를 확인했고 실제 응답에서도 `Limit=1`, `Remaining=0`, `Reset=1`을 확인했다.

수정은 거래 내역·잔고를 초기화하지 않으며, 10분 신규 분석·1분 보유 감시 주기는 유지한다. 과거 실패 이력은 보관하고 다음 분석이 정상 완료되면 활성 오류 표시가 해제된다.

## 2026-11-26 공식 가이드 재확인

공식 개요의 클라이언트×그룹별 기본 한도는 현재가·호가·최근 체결·상하한가 합산 15회/초, 종목 캔들 20회/초, 종목 기본정보 5회/초, 전체 종목 목록 1회/초, 수급 동향 10회/초, 환율·장 일정 3회/초, 랭킹 5회/초다. 수치는 변동될 수 있으며 실제 응답 헤더가 우선한다. 현재가는 한 요청에 최대 200종목, 캔들은 한 요청에 최대 200봉을 지원한다.

보유 종목만 2~5초 간격으로 묶음 현재가를 조회하는 설계는 기본 한도에 여유가 있지만, 이것은 구현 제안이지 공식 권장 주기나 적용 완료를 뜻하지 않는다. 예를 들어 현재가 묶음 1회와 5종목 호가 5회를 매초 요청하면 MARKET_DATA 합산 6회/초다. 다른 작업과 동일 Client ID의 다른 프로세스도 합산해야 하며, 웹소켓으로 체결·호가 변동분을 받는 방식도 검토할 수 있다. 전체 종목 목록·일별 정보·1분봉을 같은 속도로 반복할 이유는 없다.

과다 조회 시 429 및 대기·재시도로 유효 데이터 도착이 늦어질 수 있다. 일부 비정상 사용 의심 IP 대역은 한도가 1회/초로 낮아질 수 있다. 잦은 요청 자체가 새 체결이나 호가 갱신을 보장하지 않으며 호가 timestamp가 이전인 것은 마지막 변화 시각일 수 있다. 조회와 주문은 별개다. 공식 FAQ의 대량 반복 주문에 대한 매매 제한을 단순 시세 조회의 자동 매매 제한으로 해석하지 않는다. 조회할 때마다 토큰을 새로 발급하지 않는다. 클라이언트당 유효 토큰은 하나라 재발급하면 기존 프로세스의 토큰이 무효화된다.

웹소켓은 계정당 연결 2개, 연결당 채널×종목 구독 100개, 구독 선언 5회/초다. 같은 종목의 체결+호가는 2개 구독이다. 시세는 수신이 밀리면 중간 이벤트가 유실될 수 있어 연결·재연결·REST 보정 정책이 필요하다. 이 조사로 현재 신규 분석 10분·보유 감시 1분 정책은 바꾸지 않았다.

확인한 원문: [공식 개요](https://openapi.tossinvest.com/openapi-docs/overview.md), [시세](https://developers.tossinvest.com/docs/market-data), [웹소켓](https://developers.tossinvest.com/docs/connection), [FAQ](https://openapi.tossinvest.com/openapi-docs/faq.md).

2026-11-26 사용자 적용 요청에 따라 보유·기존 대기 주문 감시는 5초로 변경했다. 매도 종목 복기·벤치마크 추가 시세는 1분 간격, 신규 탐색은 10분 간격이다. 화면 보유 시세도 5초마다 서버에 저장된 값만 읽으며 토스증권 호출은 추가하지 않는다. 일반 상태 전체 갱신은 25초를 유지한다. 호출 중첩 방지와 오류 시 10~60초 감속을 적용했다.

2026-11-26 차트 팝업 개선: 팝업을 열 때 candles 1m을 최대 200봉씩 nextBefore로 조회한다. MARKET_DATA_CHART 공통 대기열, 사용자별 동일 범위 60초 캐시·진행 요청 공유·최대 12페이지를 적용한다. 보유 감시의 현재가/호가 요청 주기는 유지하고 저장 시세의 5초 보존 자체에는 새 API 호출이 없다. 팝업은 기존 토큰만 재사용하며 만료 토큰의 별도 발급을 하지 않는다.

2026-11-27 마감 복기 분봉 보완: 장외 유지 작업 또는 인증된 과거일 보완 버튼에서 최대 2종목·6회(캘린더 포함)로 나눠 조회한다. 같은 MARKET_DATA_CHART 전송 대기열과 사용자별 캐시를 사용하며 확인 완료된 차트는 원장에 저장해 다시 조회하지 않는다. 실패는 1분~1시간 간격으로 재시도한다. 장중 보유 감시에는 분봉 보완을 추가하지 않는다.
